# Swarm 앱별 메모리 측정과 GitOps 조정안

2026-11-05 KST 운영 조회. Swarm 4개 노드는 모두 Ready였고, 15개 서비스는 목표 태스크 30개가 모두 실행 중이었다. GitOps의 각 스택 `docker-compose.yml`과 운영 서비스의 예약·한도는 15개 모두 일치했다.

## 앱별 측정과 제안

표의 메모리는 **태스크 하나당 G**로 표시한다. GitOps 기준 `1G = 1 GiB = 1024 MiB`이며 측정값은 소수 둘째 자리까지 반올림했다. 현재 예약·한도는 원래 값을 유지하고 변경할 예약·한도는 0.05G 간격으로 정했다. 현재 사용량은 Docker stats, 최고 기록은 현재 컨테이너가 시작된 뒤 cgroup이 기록한 값이다. 범위는 NOW_START·Backup·Worker에서 확인한 복제본의 최솟값과 최댓값이다. 최고 기록에는 파일 캐시도 포함된다. Grafana 열은 최근 7일 전체 인스턴스 중 최대값이며, JVM은 힙 사용량을 5분 간격으로 집계했다. 대시는 해당 앱의 비교 가능한 RAM 시계열을 확인하지 못했다는 뜻이다.

## 노드와 수집 범위

| 노드 | 총 RAM | 사용 가능 RAM | 확인 경로 |
|---|---:|---:|---|
| NOW_START | 30.92G | 20.11G | 호스트 MemAvailable, 실행 컨테이너 10개 |
| Backup | 7.65G | 3.84G | 호스트 MemAvailable, 실행 컨테이너 7개 |
| Worker | 11.47G | 4.33G | 호스트 MemAvailable, 실행 컨테이너 9개 |
| Mac | Docker 노드 7.82G | 미측정 | Swarm 태스크 5개. 컨테이너 ID와 Grafana host_name을 대조해 JVM 4개 확인 |

Mac의 조회 시점 JVM 힙은 admin 0.146G, config 0.043G, eureka 0.066G, gateway 0.088G였다. 이 수치에는 JVM 네이티브 메모리와 캐시가 빠진다. Mac은 기존 직접 SSH 제외 설정을 따랐다. 세 노드의 Swarm 태스크 25개에서 컨테이너 전체 메모리를 읽었고, Mac 5개는 Swarm 배치와 설정을 확인했다.

최근 7일 Loki 서비스는 admin, barosteel, config, eureka, evergreen, gateway, lotto, nyang-nyang-bot이었다. Prometheus에서는 이 앱들과 otelcol-contrib를 확인했다. 스프링 부트 관측성 대시보드는 요청·지연·오류·로그 중심이다. JVM Overview와 동일한 Prometheus 데이터 소스에서 힙을 별도로 집계했다. 클러스터 전체의 컨테이너 RAM 7일 시계열은 조회되지 않았다.

스택 외 NOW_START의 `streamlink-satou0409-1`은 Docker 메모리 한도가 0(무제한), 현재 0.236G, 캐시 포함 최고 **17.0G**였다. 방송 녹화 중 RSS와 파일 캐시를 나눠 보기 전에는 한도를 산정하기 어렵다. GitOps의 cockroachdb, init, decommissioner는 예약·한도 미지정이며 실행 중인 Swarm 서비스 목록에 없었다. 템플릿은 집계에서 제외했다.

## 적용 순서

로컬 GitOps 설정에는 11개 서비스의 제안 예약값을 반영했다. 한도 축소는 barosteel, nyang-nyang-bot, coin에 반영했다. gateway와 eureka의 한도는 Mac 컨테이너 피크 확인 전까지 각각 2G, 1G로 유지한다. 표의 기존 설정과 사용량은 변경 전 운영 조회 기준이다.

1. 우선 예약만 조정한다. 표의 제안 전체를 현 복제 수로 적용하면 총 예약은 **32.75G → 21.45G**로 11.30G 줄어든다. 이는 스케줄러의 배치 여유다. 호스트 실제 사용량 절감분으로 계산하지 않는다.
2. 한도 축소 후보는 서비스 하나씩 적용한다. gateway·eureka는 Mac 전체 사용량까지 확인한 뒤 진행한다. 재배포 직후 JVM 기동, 헬스체크, 피크 트래픽, 배치 한 주기를 포함해 확인한다. JVM 컨테이너는 한도 변경 시 힙·네이티브 메모리 예산도 다시 계산될 수 있다.
3. Grafana·lotto·Portainer agent는 한도 도달 누적값 자체보다 증가 시점의 RSS, 파일 캐시, OOM, 재시작, 지연을 함께 본다. OOM이나 기동 실패가 발생하면 직전 한도로 복원한다. 호스트마다 여유 RAM이 있으므로 세 서비스의 한도 축소는 우선순위에서 제외한다.
